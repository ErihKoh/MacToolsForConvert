# MacTools — детальний план розробки для macOS

**Призначення документа:** автономний план, за яким можна продовжити розробку MacTools в іншій сесії ChatGPT або самостійно, навіть якщо попередній контекст недоступний.

## 1. Ціль проєкту

Створити персональний застосунок для macOS на Python.

Основна концепція
1. Головне вікно з категоріями інструментів, списком файлів, властивостями, чергою завдань і налаштуваннями.
2. Компактне плаваюче вікно швидких дій.
3. Перетягування файлів (drag-and-drop) у головне та швидке вікна.
4. Локальна обробка: за замовчуванням файли не відправляються в хмару, а мережеві функції не додаються без окремого рішення.
5. Оригінали за замовчуванням не перезаписуються.
6. Архітектура з окремими модулями, щоб нові інструменти можна було додавати без переписування всього застосунку.

## 2. Відоме середовище користувача

- Комп’ютер: Mac з Apple Silicon M2.
- Система: macOS; точна версія ще не підтверджена.
- Python 3.14.7 був встановлений раніше.
- Додатково встановлено Python 3.12.15 через Homebrew.
- Шлях до Python 3.12: `/opt/homebrew/bin/python3.12`.
- Рішення: використовувати Python 3.12 для цього проєкту, не видаляючи Python 3.14.
- Користувач хоче писати файли самостійно, крок за кроком, з поясненням кожного етапу.
- Не вважати, що архів зі стартовим кодом завантажений.
- Не вважати, що віртуальне середовище, залежності або перше вікно вже запущені: це потрібно перевірити в наступній сесії.

## 3. Технологічний стек

### Основні залежності

| Інструмент | Для чого | Коли додавати |
|---|---|---|
| Python 3.12 | Мова проєкту | Уже встановлений |
| `venv` | Ізольоване середовище залежностей | На початку |
| PySide6 | GUI, вікна, кнопки, списки, drag-and-drop | Етап 1 |
| Pillow | Зображення: конвертація, зміна розміру, стиснення | Етап 4 |
| `pypdf` | Базові операції з PDF, об’єднання, сторінки, текст | Етап 5 |
| PyMuPDF (`pymupdf`) | Рендеринг PDF, додаткові PDF-операції за потреби | Пізніше, якщо потрібно |
| FFmpeg | Аудіо/відео: конвертація, стиснення, кадри | Етап 8; установити окремо |
| ExifTool | Детальна робота з метаданими, якщо потрібні надійніші операції | Після базового MVP |
| `platformdirs` | Правильні шляхи для налаштувань і журналів у macOS | Етап 9 |
| `pytest` | Автоматизовані тести | Додавати поступово |
| `ruff` | Перевірка стилю та типових помилок Python | За бажанням на початку |
| PyInstaller | Пакування проєкту у `.app` | Фінальний етап |

Не встановлювати всі бібліотеки наперед. Додавати залежність лише тоді, коли її модуль починає розроблятися. Перед додаванням перевіряти сумісність з Python 3.12 і Apple Silicon.

### Системні інструменти

- Homebrew — для системних утиліт, наприклад FFmpeg та ExifTool.
- Finder — для ручного тестування та інтеграції з файлами.
- Terminal — створення середовища, запуск, діагностика.
- Редактор коду — VS Code або будь-який редактор, який зручний користувачу.

### Відповідальність модулів

- `main.py`: найкоротша точка запуску; імпортує функцію `main`.
- `app.py`: створення `QApplication`, запуск головного вікна.
- `main_window.py`: основний інтерфейс і компонування панелей.
- `quick_window.py`: компактне плаваюче вікно швидких дій.
- `drop_area.py`: універсальний віджет drag-and-drop; не повинен сам обробляти файли.
- `file_router.py`: визначає доступні операції для вибраного типу файлу.
- `task_manager.py`: черга завдань, прогрес, скасування там, де його підтримує операція; тривалі завдання виконуються не в GUI-потоці.
- `file_ops.py`: безпечні базові файлові операції, контрольні суми, розмір.
- `image_ops.py`: функції обробки зображень без логіки GUI.
- `pdf_ops.py`: функції роботи з PDF без логіки GUI.
- `media_ops.py`: обгортка над FFmpeg; запуск через `subprocess` зі списком аргументів, не через `shell=True`.
- `archive_ops.py`: архіви; перевірка шляхів перед розпакуванням.
- `metadata_ops.py`: читання та видалення метаданих.
- `config.py`: налаштування, шляхи до інструментів, параметри користувача.
- `utils/`: повторно використовувані допоміжні функції.
- `tests/`: автоматизовані перевірки.

Правило: модулі обробки не повинні імпортувати GUI. Інтерфейс викликає модуль обробки, показує прогрес і повідомляє про результат.

## 5. Етапи розробки та критерії готовності

### Етап 0 — підтвердити середовище

У Terminal:

```bash
/opt/homebrew/bin/python3.12 --version
mkdir -p ~/Projects/MacTools
cd ~/Projects/MacTools
/opt/homebrew/bin/python3.12 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install --upgrade pip
python -m pip install PySide6
```

Очікування: `python --version` показує Python 3.12.x, а `which python` веде до `~/Projects/MacTools/.venv/bin/python`.

Якщо `.venv` уже створено, не створювати його повторно без потреби — спочатку перевірити наявність каталогу та активувати середовище.

### Етап 1 — мінімальне вікно

Створити `main.py` з класом `MainWindow(QMainWindow)`, заголовком MacTools, початковим розміром вікна та центральним віджетом. Запускати командою `python main.py`.

Критерій готовності:
- вікно відкривається;
- його можна переміщувати, змінювати розмір і закривати;
- у Terminal немає traceback;
- запуск відбувається з активованого `.venv`.

Не переходити до складного UI, доки цей мінімум не працює.

### Етап 2 — каркас головного інтерфейсу

Додати:
- заголовок MacTools;
- область drag-and-drop;
- кнопки «Додати файли» та «Очистити список»;
- список доданих файлів;
- панель інформації про вибраний файл;
- вкладки або панель категорій: Зображення, PDF, Файли, Медіа, Архіви;
- статусний рядок.

Поки що кнопки можуть бути неактивними або показувати повідомлення «Буде додано пізніше». Не створювати фальшивих операцій, які нібито працюють.

Критерій готовності: інтерфейс стабільно відкривається, елементи не перекриваються, довгі шляхи читаються, вікно можна розтягувати.

### Етап 3 — додавання файлів і маршрутизація

Реалізувати `drop_area.py` та функції додавання файлів:
- приймати лише локальні URL;
- перевіряти, що шлях існує;
- не додавати директорії, якщо це ще не підтримується;
- не дублювати однаковий абсолютний шлях у списку;
- підтримувати додавання кількох файлів;
- дозволяти видалити один елемент зі списку;
- показувати помилки зрозумілим повідомленням.

`file_router.py` має класифікувати файл за сигнатурою/вмістом, якщо це можливо, а не лише за розширенням. Розширення — це підказка, а не гарантія типу.

Критерій готовності: можна додати файл кнопкою та перетягуванням; список оновлюється; неіснуючі шляхи не спричиняють аварійного завершення.

### Етап 4 — інформація про файл і базові операції

Реалізувати:
- назву, повний шлях, розширення, розмір;
- дату зміни;
- SHA-256 потоковим читанням блоками, щоб не завантажувати весь великий файл у RAM;
- кнопку «Показати у Finder» через `subprocess`/`open -R`;
- копіювання до вибраної папки з уникненням перезапису.

Критерій готовності: SHA-256 тестового файла збігається з незалежним обчисленням; великі файли обробляються блоками; існуючі файли не перезаписуються без явного підтвердження.

### Етап 5 — модуль зображень

Встановити:

```bash
python -m pip install Pillow
```

Функції:
- конвертація JPEG, PNG, WebP, TIFF, BMP;
- контроль якості для JPEG/WebP;
- зміна розміру зі збереженням пропорцій;
- поворот, якщо додано відповідний UI;
- пакетна обробка пізніше;
- створення копії без метаданих.

Важливі правила:
- оригінал ніколи не перезаписувати за замовчуванням;
- перевіряти формат перед операцією та коректно обробляти помилки;
- обробляти прозорість при конвертації у JPEG;
- враховувати EXIF orientation;
- не обіцяти повного збереження анімації, профілів кольору або всіх метаданих, якщо це не перевірено;
- видалення метаданих може впливати на колірні профілі, анімацію та додаткові дані; тестувати окремо.

Критерій готовності: протестовано на JPEG, PNG з прозорістю, WebP, великому фото та файлі з помилковим розширенням. Перевірено вихідні розміри й те, що оригінали лишилися незмінними.

### Етап 6 — PDF

Встановити:

```bash
python -m pip install pypdf
```

Функції:
- об’єднання кількох PDF;
- витягування сторінок у нові PDF;
- розділення за діапазонами сторінок;
- поворот сторінок;
- витягування тексту;
- базова інформація про кількість сторінок та метадані.

Врахувати:
- зашифровані PDF можуть вимагати пароля;
- витягування тексту не означає OCR — скановані сторінки можуть не мати текстового шару;
- PDF можуть бути некоректними або дуже великими;
- не виконувати вбудований JavaScript чи інший активний вміст;
- створювати новий вихідний файл і уникати перезапису.

PyMuPDF додавати тільки якщо потрібні рендеринг сторінок, додаткові функції чи краща продуктивність.

Критерій готовності: об’єднати два тестові PDF, витягнути текст з текстового PDF, коректно повідомити про сканований або зашифрований файл.

### Етап 7 — плаваюче вікно швидких дій

Створити `quick_window.py` як окреме компактне вікно Qt типу `Tool`:
- drag-and-drop одного або кількох файлів;
- визначення типу;
- показ лише релевантних операцій;
- швидкі дії на кшталт «Інформація», «SHA-256», «JPEG», «Витягнути текст із PDF»;
- кнопка/посилання для переходу до головного вікна.

Важливо: обидва вікна мають користуватися одним станом застосунку або спільним сервісом файлів, а не підтримувати суперечливі копії списку. Не створювати новий екземпляр головного вікна щоразу, коли відкривається quick window.

Критерій готовності: швидке вікно відкривається з головного, приймає файл, показує відповідні дії, не блокує головне вікно.

### Етап 8 — черга завдань і фонова робота

До додавання важких медіаоперацій впровадити:
- `QThreadPool`/`QRunnable` або `QThread`;
- сигнали прогресу, завершення й помилки;
- статуси «Очікує», «Виконується», «Готово», «Помилка», «Скасовано»;
- кнопку скасування, лише якщо операція може безпечно перерватися;
- обмеження кількості одночасних задач;
- не оновлювати Qt-віджети безпосередньо з робочого потоку.

Критерій готовності: довга тестова задача не заморожує UI; прогрес оновлюється через сигнали; помилки повертаються в головний потік.

### Етап 9 — аудіо та відео

Встановити FFmpeg через Homebrew:

```bash
brew install ffmpeg
ffmpeg -version
ffprobe -version
```

Модуль запускає FFmpeg через `subprocess.run()` або керований процес із масивом аргументів. Не використовувати `shell=True` для шляхів користувацьких файлів.

Функції:
- отримання технічної інформації через `ffprobe`;
- конвертація відео;
- витягування аудіо;
- конвертація аудіо;
- зміна роздільної здатності;
- стиснення з вибором пресета/якості;
- витягування кадрів.

Критерій готовності: протестувати коротке відео, аудіофайл, шлях з пробілами та файл з кириличними символами; UI лишається чутливим; stderr FFmpeg доступний для діагностики.

### Етап 10 — архіви

Почати зі стандартного `zipfile`, а зовнішні формати додавати лише за потреби.

Функції:
- перегляд списку файлів в ZIP;
- створення ZIP;
- розпакування у вибрану папку;
- контроль конфліктів імен.

Безпека:
- захист від Zip Slip: нормалізувати кожен цільовий шлях і перевіряти, що він залишається всередині каталогу призначення;
- не розпаковувати автоматично без підтвердження;
- враховувати дуже великі архіви та можливі архівні бомби;
- не перезаписувати файли мовчки.

Критерій готовності: звичайний архів працює; архів із `../` у шляху блокується; конфлікт імен обробляється без втрати даних.

### Етап 11 — налаштування, журнал і приватність

Додати `platformdirs` для зберігання налаштувань та логів у відповідних каталогах користувача macOS.

Налаштування:
- папка результатів;
- поведінка при конфлікті імен;
- максимальна кількість паралельних задач;
- які категорії показувати у швидкому вікні;
- тема та гарячі клавіші, якщо реалізовано;
- шляхи до FFmpeg/ExifTool.

Журнал:
- час, назва операції, результат, помилка;
- не записувати вміст файлів;
- за потреби дати можливість очистити журнал;
- не зберігати зайві персональні шляхи, якщо це не потрібно.

Приватність:
- не додавати телеметрію за замовчуванням;
- не додавати мережеві запити без явної потреби;
- якщо пізніше потрібне оновлення чи мережевий модуль, чітко задокументувати його;
- не просити повний доступ до диска без необхідності.

### Етап 12 — тести й стабілізація

Встановити:

```bash
python -m pip install pytest ruff
```

Перевіряти:
- файлові операції;
- контрольні суми;
- конвертацію та зміну розміру зображень;
- PDF-операції;
- архіви й захист шляхів;
- конфлікти імен;
- невалідні файли;
- шляхи з пробілами/кирилицею;
- відсутні зовнішні інструменти.

Запуск тестів:

```bash
python -m pytest
```

Перевірка стилю:

```bash
ruff check .
```

Критерій готовності: тести проходять; типові помилки показуються користувачеві, а не завершують застосунок аварійно.

### Етап 13 — пакування в `.app`

Пакувати тільки після стабілізації основних модулів.

Можливий інструмент:

```bash
python -m pip install pyinstaller
```

Потім підібрати команду PyInstaller для `main.py`, перевірити включення ресурсів і Qt-плагінів. Спершу тестувати запуск на тому самому Mac. Для передавання іншим користувачам можуть знадобитися підпис Developer ID і нотаризація Apple; це окремий етап.

Критерій готовності: застосунок запускається подвійним натисканням, не потребує активованого Terminal/venv, коректно знаходить зовнішні інструменти або пояснює, як їх установити.

## 6. Загальні правила реалізації

1. Один крок — одна невелика зміна; після неї запускати й перевіряти програму.
2. Не додавати наступний великий модуль, поки поточний не працює.
3. Давати користувачу точний шлях файла, який треба створити/відредагувати, та повний код для цього файла, якщо це початкова реалізація.
4. Пояснювати, куди вставити код і якою командою перевірити.
5. Якщо є помилка, спочатку розібрати її, а не переписувати весь проєкт.
6. Не змінювати одразу багато файлів без потреби.
7. Не зберігати всі функції в `main.py`; він має залишатися точкою входу.
8. Функції обробки не повинні залежати від Qt.
9. Тривалі операції виконувати у фонових потоках.
10. Не використовувати `shell=True` для команд, що включають користувацькі шляхи.
11. За замовчуванням не перезаписувати оригінали.
12. Не стверджувати, що формат/метадані збережені повністю, доки це не протестовано.
13. Після кожного етапу оновлювати цей план або `README.md`: що зроблено, що перевірено, що лишилося.
14. За можливості вести Git-репозиторій, але це не обов’язкова умова для першого запуску.
